# Material generation

## Contract

ProjectMaterial compiles universal recipes into persistent Unreal assets. V1 is a
closed contract, not a node graph language.

| Field | V1 value |
|---|---|
| Schema | `1` |
| Family | `surface_opaque` |
| Archetype | `landscape_basic_v1` |
| Compiler | `1` |
| Artifact kinds | `parent`, `instance` |
| Scalars | `Roughness` `[0, 1]`, `SlopeContrast` `[0.01, 16]` |
| Vectors | `LowSlopeColor`, `SteepSlopeColor` |

Recipes live in a named family folder under `Data/Materials/`. The relative folder
and safe `material_id` deterministically map to the final asset identity:

```text
Data/Materials/Terrain/M_ProjectTerrain.material.json
-> /ProjectMaterial/Generated/Terrain/M_ProjectTerrain.M_ProjectTerrain
```

Unknown fields, parameters, family names, archetypes, versions, path escapes,
duplicate identities, or cross-owner parents fail before mutation. A new parameter or
archetype requires a reviewed schema/compiler version; do not widen V1 in place.
Every instance parent must also be the exact output of a parent recipe in the current
discovered recipe set. Existing package bytes cannot substitute for a removed recipe.

The first accepted production consumer uses the exact Terrain parent/default pair:

```text
/ProjectMaterial/Generated/Terrain/M_ProjectTerrain
/ProjectMaterial/Generated/Terrain/MI_ProjectTerrain_Default
```

Its graph is intentionally bounded to vertex-normal slope classification, two colors,
slope contrast, and roughness. Macro variation, textures, Landscape coordinates, and
noise are not implicit V1 capabilities; adding one requires a separately reviewed core
extension.

## Semantic identity

The accepted identity includes normalized recipe semantics, compiler fingerprint,
exact launcher-engine version and changelist, final object path, and the accepted
parent package hash for an instance. The compiler fingerprint is generated by UBT from
`ProjectMaterialEditor.Build.cs`, the sorted non-test `ProjectMaterialEditor` C++/header
source set, and its schemas. The same exact file set is registered with UBT through
`ExternalDependencies`; this is required because schema files live outside normal C++
makefile inputs. A rebuilt build-definition, behavior, or schema change therefore
invalidates the UBT makefile and prior semantic identity without relying on a
hand-maintained version string. Test-only source is deliberately excluded from both
the fingerprint and the external-dependency set. Formatting-only recipe JSON changes
are no-ops.

A skip is accepted only when both semantic identity and current package SHA-256 match
the manifest. Missing or corrupt bytes regenerate. An instance invalidates only when
its own recipe or exact parent package changes.

Manifest paths are owner-relative. Machine paths and personal host identities are not
stored in repository authority.

## Mutation lifecycle

Production mutation has two owners:

```text
host wrapper
  -> shared project generated-content lock
  -> same-project Editor exclusion
  -> exact output and manifest snapshot
  -> durable transaction journal
  -> one-shot launcher UnrealEditor-Cmd
       -> validate all recipes
       -> clean reconstruction at final package identity
       -> compile, save, release, reload, verify
       -> promote aggregate manifest last
  -> authenticate receipt
  -> retain Current/Previous evidence and one exact prior rollback bundle
  -> remove run scratch
```

Failure, rejection, crash, or timeout is handled only after the child process exits.
The host restores the exact prior assets and manifest, or exact prior absence, then
removes the journal and run scratch. A surviving journal is recovered under the same
global lock before another mutation starts. The latest rejection evidence is bounded
to one directory and is removed by the next accepted run.

After accepted production regeneration, `RollbackPrevious` retains only the exact
pre-run output/manifest state and its presence receipt. The next accepted regeneration
replaces it, so rollback storage cannot accumulate.

The commandlet requires a matching host transaction identity for regeneration.
Existing output replacement without that owner is rejected.

## Orphans

Normal generation reports generated packages not owned by the accepted recipe set.
It does not delete them. Explicit `-CleanupOrphans` removes only unreferenced packages
inside `Content/Generated/`; referenced or out-of-root assets are retained.

## Verification

Focused C++ tests own recipe, graph, parameter, identity, integrity, idempotence,
dependency-locality, process-ownership, reload, and orphan behavior. The wrapper
integration test owns real fresh-process generation, shared-lock contention,
zero-write rerun, injected post-save failure, exact rollback, and clean replacement.

The core test mount is confined to `tmp/material/generation/` and is owner-cleaned.
Kazan and production materials are not mutated by core-only tests.
